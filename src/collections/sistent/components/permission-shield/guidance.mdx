Providing actionable, transparent feedback is essential when guiding users through permission-controlled cloud environments. The following guidelines help teams effectively implement authorization gates.

<a id="When-to-Use">
  <h2>When to Use: Shield vs. Hide</h2>
</a>

Different UI surfaces require different authorization degradation strategies. Sistent supports two primary actions: **`showShield`** and **`hide`**.

<h3>Use `showShield` (or `PermissionShield`) when:</h3>

<ul>
  <li><p><b>In-Page Affordances:</b> The user is on a workspace, project, or settings page where an action button (e.g., "Deploy Pattern", "Add Node", "Export Telemetry") is visible to all members but executable only by admins or operators.</p></li>
  <li><p><b>Educational Discoverability:</b> You want the user to know that a premium feature or capability exists, understand what role or key is required, and request access from an administrator.</p></li>
  <li><p><b>Contextual Forms:</b> Fields or inputs in a form where certain advanced properties are read-only for standard users.</p></li>
</ul>

<h3>Use `hide` (omit from render) when:</h3>

<ul>
  <li><p><b>Primary Navigation Menus:</b> Navbars and sidebar menus should hide unreachable top-level sections and pages to prevent menu bloat and clutter.</p></li>
  <li><p><b>Destructive Admin Consoles:</b> Management consoles that are irrelevant to non-admin tenants.</p></li>
  <li><p><b>Extension Points:</b> Pluggable cards or sidebar panels intended only for privileged roles.</p></li>
</ul>

<a id="Anatomy">
  <h2>Anatomy of the Shield & Tooltip</h2>
</a>

The `PermissionShield` tooltip contains structured metadata designed to resolve access requests efficiently:

<ol>
  <li><p><b>Authorization Header:</b> Clear title indicating <code>AUTHORIZATION REQUIRED</code>.</p></li>
  <li><p><b>Requirement Combinator:</b> Explains whether the user requires all keys (<code>Needs all of:</code>) or any single key (<code>Needs any of:</code>).</p></li>
  <li><p><b>Key Metadata Blocks:</b> For each unmet key, displays:</p>
    <ul>
      <li><p><b>Copy Key ID Trigger:</b> Clicking the key icon copies the canonical UUID to clipboard for sharing with system administrators.</p></li>
      <li><p><b>Permission Function Name:</b> Clear human-readable action name (e.g., <em>"Create Workspace"</em>).</p></li>
      <li><p><b>Description:</b> Explanatory copy clarifying what capability the key grants.</p></li>
      <li><p><b>Category & Subcategory Chips:</b> Granular taxonomy tags for quick categorization.</p></li>
      <li><p><b>Key Reference Link:</b> Direct link to official permissions documentation.</p></li>
    </ul>
  </li>
  <li><p><b>Active User Context:</b> Displays the current user's name, active organization, and <strong>Assigned Roles</strong>.</p></li>
  <li><p><b>Support Callout:</b> Prompt directing the user to contact their organization administrator.</p></li>
</ol>

<a id="User-Context-Contract">
  <h2>The Assigned Roles Contract</h2>
</a>

<p>
  <strong>Critical Invariant:</strong> The user context rendered inside the tooltip and 403 context cards must <em>always</em> reflect the roles the user is <strong>assigned</strong> in the active organization, never the organization's total role catalog.
</p>

<ul>
  <li><p>Displaying the org role catalog mistakenly informs users that they possess roles they do not hold.</p></li>
  <li><p>When a user holds no assigned roles in the active tenant space, the component cleanly reports <code>Role(s): None</code>.</p></li>
</ul>

<a id="Multi-Tenancy">
  <h2>Multi-Tenant Organization Switching</h2>
</a>

When users encounter a 403 Access Denied page, the `useAccessibleOrgs` hook queries other organizations the user belongs to in parallel. If the user possesses the required permission in a sibling organization, an Organization Switcher dropdown allows instant switching without leaving the flow.

<a id="Accessibility">
  <h2>Accessibility & Keyboard Navigation</h2>
</a>

<ul>
  <li><p><b>Non-Obstructive Dimming:</b> Guarded children receive <code>opacity: 0.5</code> and <code>pointer-events: none</code> while remaining in the accessibility tree.</p></li>
  <li><p><b>Focusable Shield Trigger:</b> The shield icon trigger is keyboard-focusable with <code>tabIndex={0}</code> and triggers via <kbd>Enter</kbd> or <kbd>Space</kbd>.</p></li>
  <li><p><b>Screen Reader Labels:</b> Copy triggers supply descriptive <code>aria-label</code> tags (e.g. <code>aria-label="Copy key ID for Create Workspace"</code>).</p></li>
  <li><p><b>Click-Away Dismissal:</b> Tooltips automatically close when the user clicks outside or focuses another element.</p></li>
</ul>

<a id="Performance">
  <h2>Performance Tips</h2>
</a>

<ul>
  <li><p><b>Memoized Evaluator:</b> Pass a stable or memoized <code>userHasPermission</code> function to <code>PermissionProvider</code> to avoid unnecessary re-renders of the component tree.</p></li>
  <li><p><b>Lazy Org Evaluation:</b> The <code>useAccessibleOrgs</code> hook is designed specifically for 403 error pages. Do not mount it on high-frequency navigation bars.</p></li>
</ul>
