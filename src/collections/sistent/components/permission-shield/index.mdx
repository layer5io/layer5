The **Permission Shield** component provides contextual authorization feedback in cloud-native user interfaces. Rather than silently disabling controls without explanation, `PermissionShield` presents an intuitive shield overlay that informs users of required permissions, missing permission keys, and active user/role context.

<a id="Overview">
  <h2>Overview</h2>
</a>

In modern multi-tenant enterprise applications, access control is dynamic and fine-grained. Users frequently encounter actions or views that require elevated roles or specific capability keys.

The Sistent Permission System consists of three synergistic building blocks:

1. **`PermissionProvider`**: The root context provider supplying permission evaluators and user metadata to the entire component tree.
2. **`PermissionShield`**: The declarative UI wrapper that overlays actionable tooltips onto unauthorized affordances.
3. **`PermissionSessionContext`**: The standalone authorization context component displayed inside tooltips and on dedicated 403 error pages.

<a id="Variants">
  <h2>Variants</h2>
</a>

`PermissionShield` offers two distinct presentation variants depending on the density and layout requirements of the guarded element.

<h3>Inline Variant (Default)</h3>

The **Inline** variant centers a security shield trigger on the right side of the guarded element. It is ideal for full-width buttons, form inputs, list items, and standard rectangular controls.

<h3>Badge Variant</h3>

The **Badge** variant renders a compact shield badge anchored to the corner of the guarded affordance. It is designed for icon buttons, compact toolbars, chips, and standalone action pills.

<a id="Permission-Context-Card">
  <h2>Permission Session Context Card</h2>
</a>

When users navigate directly to a restricted URL or access-denied route, `PermissionSessionContext` renders as a full-page **card** variant. It provides complete transparency into the missing keys, categorized tags, and assigned roles.

<a id="Authorized-State">
  <h2>Authorized State (Pass-Through)</h2>
</a>

When the active user possesses the required permission key, `PermissionShield` seamlessly passes through the child component without dimming, overlaying icons, or intercepting pointer events.

<a id="Key-Features">
  <h2>Key Features</h2>
</a>

<ul>
  <li><p><b>Declarative Key Specs:</b> Accepts single permission keys or composite logical sets (<code>anyOf</code> / <code>allOf</code>).</p></li>
  <li><p><b>Interactive Key Copying:</b> Users and administrators can copy the exact permission UUID to clipboard with one click.</p></li>
  <li><p><b>Assigned Role Clarity:</b> Context cards show the user's actual assigned roles in the active organization, preventing confusion with the global role catalog.</p></li>
  <li><p><b>Conflict-Free Tooltips:</b> Global event coordination guarantees only one shield tooltip is open across the entire interface at any time.</p></li>
  <li><p><b>Multi-Tenant Org Switching:</b> Pairs with the <code>useAccessibleOrgs</code> hook to guide users to switch to an authorized organization.</p></li>
</ul>
